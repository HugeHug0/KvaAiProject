# KVA AI — демо-лендинг

Одностраничный лендинг-презентация вымышленного продукта «KVA AI» (ИИ-агенты для бизнеса).
Сделан как **полностью статическая демо-страница**: без сборки, без фреймворков, без бэкенда.

```
landing/
└── index.html    # весь лендинг: разметка + CSS + JS в одном файле
```

Файл один — это одна сетевая загрузка и ноль внешних зависимостей
(нет CDN, нет шрифтов, нет картинок: иконки — inline-SVG, шрифты — системные).

## Как открыть

Просто **двойной клик по `index.html`**. Всё работает офлайн, включая форму.

Если хочется «как на хостинге» (по адресу `http://`, а не `file://`) — подойдёт любой
статический сервер, например встроенный в Python:

```bash
python -m http.server 8000
# затем открыть http://127.0.0.1:8000/
```

## Форма заявки → Google Apps Script

Заявка отправляется **fetch‑запросом на Google Apps Script** (ваш бесплатный
server‑less‑скрипт внутри Google) — никакого собственного бэкенда и хостинга
не требуется, всё работает из одного `index.html`.

Что происходит по нажатию «Отправить заявку»:

1. Поля проверяются на клиенте и подсвечиваются: имя, почта, телефон, согласие
   (обязательное). Honeypot‑поле защищает от ботов.
2. Кнопка показывает спиннер — запрос уже в пути (`fetch` к вашему GAS‑скрипту).
3. Данные POST‑ятся на GAS в формате JSON (`Content-Type: text/plain;charset=utf-8` —
   почему именно так, см. раздел ниже), имена полей совпадают с заголовками
   колонок таблицы: `name`, `email`, `phone`, `company`, `team_size`, `task`.
4. Ответ получен → появляется экран успеха: рисующаяся галочка, конфетти и блок
   «что дальше».

Если `fetch` не удался на сетевом уровне (нет сети, `file://` вместо `http://`,
плохой URL), страница плавно переключается в демо‑режим и всё равно показывает
«спасибо» — чтобы сайт не зависал и оставался работоспособным.

### Почему `mode: 'no-cors'` и `Content-Type: text/plain`

Это не случайность, а единственный способ отправить данные в GAS из браузера без бэкенда.

Google Apps Script **не умеет отвечать на preflight‑запрос `OPTIONS`**: у `ContentService`
нет API для установки заголовков ответа, поэтому `Access-Control-Allow-Origin` в ответе
не появляется. Отсюда цепочка проблем:

| Что отправляем | Что делает браузер | Результат |
|---|---|---|
| `Content-Type: application/json` | тип **не** входит в CORS‑safelisted список → сначала шлёт `OPTIONS` preflight | GAS отвечает `200`, но без `Access-Control-Allow-Origin` → браузер блокирует POST: <br>`Response to preflight request doesn't pass access control check` |
| `Content-Type: text/plain;charset=utf-8` | тип **входит** в CORS‑safelisted список → preflight не нужен, идёт сразу `POST` | Запрос доходит до GAS, `doPost` выполняется, строка пишется в таблицу |

Второй элемент — `mode: 'no-cors'`: он говорит браузеру «ответ читать не буду», поэтому
оплаченный отсутствием заголовков ответ не считается ошибкой. Ответ приходит «opaque»
(его содержимое недоступно из JS), и мы определяем успех по отсутствию сетевой ошибки.
Для лид‑формы этого достаточно: заявка в таблице есть, посетитель видит «спасибо».

В `doPost` при этом **ничего менять не нужно** — тело запроса по‑прежнему приходит как
`e.postData.contents`, и `JSON.parse(e.postData.contents)` работает как есть.

> Проверка после первой отправки: откройте DevTools → Network. Должен быть **один**
> запрос `exec` методом `POST` и **без** строки `preflight`. Затем загляните в таблицу —
> строка должна появиться. Если строки нет, значит деплой GAS закрыт: в
> «Развернуть» → «Веб‑приложение» доступ должен быть «Все, даже анонимные».

### Как подключить (3 минуты, бесплатно)

1. Откройте https://script.google.com/ → **Новый проект**.
2. Вставьте туда код (он пишет каждую заявку в строку Google‑таблицы):

```js
function doPost(e) {
  const id = 'ВАШ_ID_ТАБЛИЦЫ';
  const sheet = SpreadsheetApp.openById(id)
    .getSheetByName('Лист1') || SpreadsheetApp.openById(id).getActiveSheet();
  const d = JSON.parse(e.postData.contents);
  sheet.appendRow([new Date(), d.name||'', d.email||'', d.phone||'', d.company||'', d.team_size||'', d.task||'']);
  return ContentService
    .createTextOutput(JSON.stringify({ result: 'success' }))
    .setMimeType(ContentService.MimeType.JSON);
}
```

3. **«Развернуть» → «Веб‑приложение»** →
   *Исполнить как:* «Я», *Доступ:* «Все, даже анонимные» → **Развернуть** →
   скопировать URL вида `https://script.google.com/macros/s/AKf…/exec`.
4. Вставить этот URL в `index.html` — в константу `GAS_URL` (в текущей сборке он
   уже вписан). Если заводите новую таблицу/скрипт — просто замените строку:

```js
const GAS_URL = 'https://script.google.com/macros/s/ВАШ_ID/exec';
```

Готово — заявки с сайта попадают в вашу таблицу в реальном времени. Если `GAS_URL`
оставить пустым (`''`), форма уйдёт в демо‑режим (обработчик упадёт в `.catch`).

## Адаптивность

| Диапазон | Что меняется |
|---|---|
| > 1080px | Полная двухколоночная раскладка, эффект за курсором и наклон карточек |
| ≤ 1080px | Одноколоночные hero и демо-панель, карточка без 3D-наклона, уменьшенные заголовки |
| ≤ 860px | Скрыта навигация в шапке → бургер-меню на весь экран, сетки в одну колонку |
| ≤ 620px | Скрыты декоративные плашки и шапка-CTA, форма в одну колонку, кнопки на всю ширину, тач-цели ≥ 44px |
| ≤ 520px | Двухколоночная сетка метрик, компактные табы |
| ≤ 400px | Минимальные отступы и размеры (iPhone SE/Fold) |
| `hover:none` | Отключены бесконечные декоративные анимации и эффект за курсором |
| `prefers-reduced-motion` | Отключены все анимации и плавная прокрутка |

Дополнительно: `viewport-fit=cover` + `env(safe-area-inset-*)` — контент не заезжает
под «челку» и полосу прокрутки на смартфонах; поля формы на мобильных имеют
`font-size:16px`, чтобы iOS Safari не зумил страницу при фокусе.

## Тёмная тема и нативные элементы

Нативные контролы браузера по умолчанию светлые, на тёмной странице это выглядит инородно.
Что сделано:

* **`color-scheme: dark`** на `:root` — браузер узнаёт, что тема тёмная, и рисует тёмными
  системные элементы: выпадающий список `<select>`, скроллбары, «лапку» изменения размера
  у `textarea`. Без этого они остаются белыми пятнами.
* **`<option>` заданы явно** (`background-color:#0d1020; color:var(--text)`, выбранный —
  фирменный фиолетовый). Это исправленный баг: список открывался с белым системным фоном,
  а текст наследовал светлый `--text`, поэтому пункты выглядели пустыми и читались только
  при наведении (когда появлялась системная синяя подсветка).
* **Автозаполнение Chrome** (`:-webkit-autofill`) перекрыто `inset`-тенью: браузер заливает
  поле своим светлым фоном, а `background-color` для `:autofill` игнорирует — работает только
  `box-shadow`, поэтому тёмная тема сохраняется и при автозаполнении.

## Маска телефона

Поле телефона форматируется на каждый ввод: `8…` → `+7…`, максимум 11 цифр,
итоговый вид `+7 (999) 123-45-67`. Форматирование выполняет `formatPhone()`,
а обработчик просто переписывает значение целиком:

```js
phoneInput.addEventListener('input', () => {
  phoneInput.value = formatPhone(phoneInput.value);
});
```

Позицию каретки специально не восстанавливаем: маску заполняют слева направо, и после
переформатирования курсор ожидаемо оказывается в конце строки. Попытка «сохранять позицию
по количеству цифр слева» здесь не работает: `formatPhone` сам добавляет цифру кода страны
(«7»), из-за чего счётчик сдвигается и каретка прыгает назад — проверено и откачено.

## Производительность

Что сделано для отсутствия лагов при прокрутке:

* **Ни одного `backdrop-filter`** — он заставляет перерисовывать элемент на каждом кадре скролла.
* **Все бесконечные анимации — только `transform`/`opacity`**, то есть уходят на композитор.
  Анимация CSS-переменной `--angle` (@property) для вращающейся рамки заменена на `rotate`;
  ключевые кадры `gradPan` (анимация `background-position`), `mockFloat` (анимация 3D-углов
  карточки) и `drift2` удалены полностью — каждый из них заставлял браузер перерисовывать
  элемент в каждом кадре.
* **Появление блоков при прокрутке** — `IntersectionObserver` с порогом 0 и нижним `rootMargin`
  (срабатывает и для блоков выше экрана, где порог в 15% был недостижим) плюс страховка: через
  4 секунды всё, что уже в экране, показывается принудительно, — контент не может остаться невидимым.
* **Лента логотипов встаёт на паузу, когда уходит за пределы экрана** (`IntersectionObserver`
  добавляет класс `is-off`) — композитор не тикает вхолостую.
* **Карточка-дашборд больше не вращается в 3D**: наклон остался статичным, а «плавание» идёт
  через `translateY`, поэтому Chrome не перерастрирует её каждый кадр.
* **`content-visibility` не используется** — экономия на отрисовке не окупала прыжки и лишний layout.
* **`overflow-x:clip`** вместо `hidden` — не создаёт scroll-контейнер, прокрутка остаётся композитной.
* **`will-change` не висит постоянно** — только у декоративного пятна и свечения за курсором;
  у карточек и тарифов убран.
* **Свечение за курсором уменьшено** с 460 до 340 px — дешевле композитинг.
* **JS-обработчик скролла** не читает `scrollHeight` в каждом кадре (кэшируется, пересчёт на `resize`/`load`),
  вызывается через `requestAnimationFrame`, слушатель `passive` и меняет классы только при смене
  состояния, а не каждым кадром.
* **Полоса прогресса чтения** в поддерживающих браузерах рисуется через `animation-timeline: scroll()`
  силами браузера — JS её вообще не трогает.
* **Свечение за курсором останавливает `requestAnimationFrame`**, когда догнало мышь.
* **В обработчике движения мыши по карточке нет ни одного чтения layout.**
  `getBoundingClientRect()` вызывается один раз на кадр внутри `requestAnimationFrame`, а не на
  каждое событие: иначе браузер пересчитывал бы раскладку сотни раз в секунду (layout thrashing).
* **На мобильных декоративные вечные анимации выключены целиком** (медиазапросы `max-width:860px`
  и `hover:none`): пятна, «плавание» карточки, пульсация точек и мягкая тень в 80 px заменены
  статикой — меньше работы GPU и расхода батареи.
* Один HTTP-запрос, ~120 КБ без сжатия (≈29 КБ gzip), ноль внешних ресурсов.

Чтобы отдать страницу ещё быстрее на хостинге — включите gzip/brotli и длинный
`Cache-Control` для `index.html`.

## Что менять под себя

* Тексты, тарифы, отзывы, FAQ — прямо в `index.html`, всё помечено комментариями-секциями
  (`<!-- ... -->` и `/* ---------- N. ... ---------- */`).
* Палитра — CSS-переменные в начале `<style>`: `--brand`, `--brand-2`, `--brand-3`, `--bg`.
* Скорость появления блоков при прокрутке — переменная `--ease-out` и класс `.reveal`
  (задержки задаются инлайновым `transition-delay`).
* Ссылка «Политика конфиденциальности», `canonical` и `og:*` — демонстрационные заглушки,
  перед публикацией замените на реальные.

## Ограничения

* Данные в интерфейсе (2 400+ компаний, 80% рутины, отзывы, цены) — выдуманные, для демонстрации.
* Персональные данные отправляются на ваш Google Apps Script (см. «Форма заявки»), а
  пока URL не вставлен — форма работает в демо‑режиме (fallback на `setTimeout`).
* Ссылка «Политика конфиденциальности» и `og:*` — демонстрационные заглушки;
  перед публикацией замените на реальные, а также подпишите согласие по 152‑ФЗ.
